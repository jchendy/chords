# Working on this repo

A dependency-free guitar web app: no build, no bundler, plain scripts on
`window.GT`. Serve it with `python3 serve.py` (port 8777, no-store) and run
the tests by opening `tests.html` (`window.TEST_RESULTS`).

## Before touching the styles, band patterns or guitar parts

Read [docs/STYLES.md](docs/STYLES.md). It is the method: where the data
lives (`review/proposals*.js` is the source of truth, merged over the base
data by `js/styles.js`), the rule that parts are written from a style's
idiom and never from a recording, how a part is written and placed on the
neck, the register rule, double stops by shape, the thumb on the bass
strings, what the band pattern's fields mean, how to measure rather than
assume, and the order to add a style in. What the research found — every
genre's players and records, every part's reasons — is in
[docs/STYLES-CATALOGUE.md](docs/STYLES-CATALOGUE.md), generated by
`node tools/styles-doc.js`; regenerate it when the proposals change.

## Habits this repo keeps

- Measure rather than assume: when a claim is made about the parts, realise
  them and count (`node tools/sweep.js`, `node tools/reach.js`, the review
  page's `card.getState()`).
- Every new test is sabotage-checked: break the thing it holds, see it
  fail, put it back.
- Bugs go in `BUGS.csv`, work items in `TODO.csv`; items are marked done
  with a resolution, never deleted; nothing goes in TODO unless asked. Both
  files keep CRLF line endings.
- Samples: only with a licence that allows it, and a comment in the code
  saying where they came from and why it is fine.
- Parts: designed from the idiom, never from recordings; no signature riffs;
  artists and songs are reference points only.
- `README.md` describes every file and the ideas behind them; keep it true.
